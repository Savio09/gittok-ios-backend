# GitDiagram video study and GitTok's contribution-decision gap

November 6, 2026. Research/process record; no application implementation in this
change and no human-participant acceptance claim.

The owner tested the current walkthrough and reported that it still does not
give enough understanding to decide whether a project is worth contributing to.
This is a product outcome finding beyond the earlier tests for citation integrity,
publication gates and HTTP/native behavior.

At the owner's request, REA was cloned to
`/Users/fdeclan/Public/gitstack/research/rea` and used through its published CLI
for an actual isolated-browser capture of GitDiagram Reels. The source study
used GitDiagram commit `2ae1828cbc0800b8493944a29aa3d0bc30083edf` and three scoped
reviewer agents. REA captured a real React film's changing counter/state visuals,
accessibility and network observations; its owned browser cleanup was confirmed.
Source inspection traced director → scene designers → deterministic layout →
narration alignment → owned stage → optional MP4 export. This pipeline does not
require running the subject repository.

The complete source-cited study, screenshots, scenario and raw REA evidence are
in [the shared research record](../../../docs/2026-11-06-gitdiagram-video-study/README.md).
That record separates source-derived findings, observed playback, historical
experiments and proposed implementation.

New concrete findings:

- GitTok's story contract has no visual subjects, timed beats or narration.
- The current native player presents paragraphs and advances every five seconds;
  the final Glow workflow contains 146 words on one page.
- Required purpose/workflow coverage does not ensure a practical product story
  or a supported next contribution investigation.
- Semantic handoff content is mapped to setup, so “Before you clone” can display
  the generic “Next step” label instead of development guidance.
- Device-local shortlisting already works. The missing experience includes
  remembering a project's appeal and next action, rather than rebuilding save
  infrastructure.

The proposed direction is a practical-first visual story within the existing
Folio design, using accepted claim references, a compact typed visual vocabulary,
one narration clock, contextual sources and the existing shortlist. A complete
phone demonstration and contribution-decision assessment should precede broader
generation/infrastructure work. Production remains generic across repositories;
one reviewed reference film is an acceptance fixture, not a repository allowlist.

The earlier source-quality work remains useful, but its successful checks did
not establish product comprehension. This study does not mark SAV-52 complete,
perform new paid generation, or claim Azure target execution.
