# Cold previews and live discovery — November 7, 2026

The owner reopened the app after a reported restart and still received source reports. The earlier health-only restart check did not establish a usable preview. This repair follows that failure and the owner's subsequent authorization of a $50 total testing ceiling and a live public feed. Folio remains the visual design; authentication, personalization and Azure execution are deferred.

## Root causes and changes

At the configured Sol prices, the writer's 67,584-byte future-transcript reserve exceeded its entire $0.25 share of the original $0.50 job limit, forcing submission before any source tools. Saturating the initial request with a long code prefix could also crowd out the README and useful implementation lines. The generic repair fits purpose/code footholds against research plus final composition, bounds tool windows to 4 KiB of complete original lines, and composes through an independent fresh request carrying every successful requested window, exact offsets, identity and limitations. Research continuations retain their reasoning/tool history; raw reasoning is not needed in an independent final composition packet. Cumulative costs and exact source checks remain enforced.

The app now shows preparation/failure status above its source preview. A failed generation remains an honest source fallback rather than a fabricated story. Operator diagnostics distinguish ledger exhaustion from provider failures and expose bounded revision-review preflight quantities without logging source bodies or model prose.

Source exactness proved insufficient as a quality bar. An initially accepted Excalidraw story explained only a sharing helper; another added product purpose but spent a third of its words on import errors and overstated decode/parse success. PocketBase used unexplained hook/continuation jargon. Writer, correction and independent reviewer requirements now establish the whole product first, follow one practical successful task in order, explain framework jargon, preserve necessary guards and omit unrelated error branches. These are generic requirements, not repository-name exceptions. The final two artifacts below passed separate adversarial semantic/product reviews. A suspected visual focus defect was ruled out by reading the renderer: indexes are one-based and zero means no highlight.

The production feed previously used `selection.Curated()` with exactly four repositories. It now uses the verified public-only GitHub credential and paginated public search. Its explicit cohort is popular new repositories: created in the last 30 days, at least 20 stars, sorted by stars, excluding forks/archive/private/unknown-public items. Each page has up to 25 raw provider results; the search horizon is 1,000. This is not measured star growth or exhaustive discovery. The app states these criteria. See [the feed contract and limits](public-discovery.md).

Fresh review reproduced an outage amplification bug: twenty concurrent same-page failures made twenty provider calls. A ten-second shared error cooldown now coalesces this burst; successful/empty pages share a ten-minute bounded cache. Physical search requests are paced and do not automatically retry. Invalid/expired cursors recover through refresh; live ranked pages deduplicate stable GitHub identities and slugs, including renames.

## Practical limits

Accepted walkthrough bodies remain process-local. Restart loses prepared bodies; cold regeneration now has real evidence but not a guaranteed outcome for every repository. Bounded acquisition, model availability, semantic rejection or budget refusal can still produce a clearly labeled source fallback. These results extend the earlier library/CLI controls with frontend/backend cases; they do not establish universal success or human participant acceptance. AI reviewers performed the semantic assessments.

Public search is a changing popularity-ranked cohort, not a snapshot or a star-growth measurement. Metadata cards appear before source analysis; classification can remain unknown. Authentication, true personalization, durable visibility-safe artifact caching, broader participant evaluation and isolated runtime capture remain subsequent work. Source visuals are illustrations, not recordings of running repositories.
